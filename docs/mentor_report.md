# Звіт про розробку — Vape Shop Platform

## Загальний огляд

Проект являє собою повноцінну платформу для вейп-шопу, що складається з трьох компонентів:

- **Telegram-бот** — основний канал комунікації з клієнтами (каталог, замовлення, розсилки)
- **Адмін-дашборд** — веб-панель управління (FastAPI + Jinja2)
- **Публічний сайт** — вітрина товарів для клієнтів

**Стек:** Python, FastAPI, aiogram 3, asyncpg, PostgreSQL, aiohttp, Groq AI API  
**Деплой:** Railway (два сервіси — веб + бот, спільна PostgreSQL база)

## Нові функції

### 🤖 ІІ Контент-менеджер

Найбільша нова функція. Сторінка `/content-manager` в дашборді дозволяє адміну генерувати маркетинговий контент за допомогою штучного інтелекту.

**Як це працює:**

1. Адмін заповнює форму з даними товару:
   - Назва, бренд, категорія
   - Об'єм, міцність, VG/PG (для рідин)
   - Ціна, тип смаку, додаткові нотатки

2. Натискає **"✨ Згенерувати контент"** — система звертається до **Groq API** (модель `llama-3.1-8b-instant`) і одночасно генерує два типи контенту:
   - **Telegram-пост** — живий, дружній текст 150–220 символів з емодзі та закликом до дії
   - **SEO-опис для сайту** — структурований текст 80–120 слів з ключовими словами

3. Адмін може відредагувати результат вручну, регенерувати або одразу публікувати.

**Кнопки публікації після генерації:**

| Кнопка | Що робить |
|--------|-----------|
| 🔄 Регенерувати | Генерує новий варіант тексту зберігаючи дані форми |
| 📤 Розіслати клієнтам | Надсилає Telegram-пост всім підписникам. Можна додати фото — воно відправиться разом з підписом |
| 🌐 Додати на сайт | Зберігає товар в базу даних: назва, бренд, категорія, ціна, кількість, AI-опис як картка товару. Фото завантажується через Telegram і зберігається як `file_id` |
| 🚀 Опублікувати скрізь | Виконує обидві попередні дії одночасно — розсилка клієнтам + додавання товару на сайт і в каталог бота |
| 📋 Копіювати | Копіює SEO-опис в буфер обміну |

**Технічна деталь:** ІІ не вигадує характеристики — system prompt явно забороняє додавати дані яких немає у вхідних полях.

### 📢 Розсилки з дашборду

Раніше розсилки можна було робити тільки командою `/broadcast` безпосередньо в Telegram-боті. Тепер це доступно через дашборд.

Сторінка `/broadcasts` містить:
- Форму з textarea і лічильником символів
- Чекбокс "Додати кнопку 🛒 Замовити" — опціональна inline-кнопка для товарних постів
- Таблицю з історією всіх розсилок (дата, текст, скільки отримали, скільки помилок)

---

### 🖼 Фото товарів через дашборд

Раніше фото можна було додати до товару тільки через бота (адмін надсилав фото в чат боту). Тепер в модалках **"Додати товар"** і **"Редагувати"** є поле для завантаження фото з комп'ютера.

**Архітектура:**
- Фото завантажується через окремий AJAX-запит до `/products/upload-photo`
- Бекенд надсилає фото в Telegram Bot API, отримує `file_id`, одразу видаляє повідомлення
- `file_id` зберігається в БД — фото доступне на сайті через проксі `/api/photo/{file_id}`
- Під полем одразу видно статус: ✅ успіх або ❌ конкретна помилка

---

### 🔔 Сповіщення про наявність товару (waitlist)

Функція існувала в боті, але спрацьовувала тільки при поповненні через команду `/restock` в Telegram. Якщо адмін поповнював залишок через дашборд — клієнти не отримували сповіщення.

Тепер кнопка **"📦 Поповнити"** в дашборді автоматично:
1. Оновлює кількість в БД
2. Знаходить всіх клієнтів з листа очікування на цей товар
3. Надсилає їм Telegram-повідомлення: _"Товар X знову є в наявності!"_
4. Очищує лист очікування

## Виправлені баги

### 🔴 Критичні

**500 Internal Server Error на `/content-manager`**  
Причина: FastAPI 0.136 змінив API шаблонізатора Jinja2. Старий виклик `TemplateResponse("template.html", {"request": request})` передавав словник як ім'я шаблону, що спричиняло `TypeError: unhashable type: 'dict'` в LRU-кеші.  
Виправлення: оновлено на новий синтаксис `TemplateResponse(request, "template.html")`.

**Логін повертав JSON 422 замість HTML форми**  
Причина: FastAPI повертає JSON-відповідь коли обов'язкове поле форми (`password`) відсутнє у запиті. Браузер при натисканні Enter без вводу паролю надсилав порожній POST.  
Виправлення: змінено `Form(...)` на `Form(default="")` + явна перевірка на порожній рядок + атрибут `required` на input.

**21-денні нагадування надсилались щодня повторно**  
Причина: SQL-запит в планувальнику не перевіряв чи клієнт вже отримав нагадування.  
Виправлення: додано `NOT EXISTS` підзапит до таблиці `reminder_logs` з перевіркою за останні 30 днів.

### 🟡 Середні

**Фото не зберігалось при завантаженні через дашборд**  
Причина: функція `upload_photo_to_telegram` надсилала фото, отримувала `file_id`, але потім виконувала `deleteMessage` без `async with` — це кидало виключення, яке ловилось зовнішнім `except` і функція повертала `None`.  
Виправлення: `deleteMessage` обгорнуто у власний `try/except`.

**Кнопка "Замовити" в розсилці не відкривала бот**  
Причина: `BOT_USERNAME` в Railway зберігався з символом `@`, URL виходив `https://t.me/@username` — невалідний формат для Telegram.  
Виправлення: `.lstrip("@")` перед формуванням URL.

**Товари з контент-менеджера йшли в "Інші рідини" в боті**  
Причина: при додаванні товару через "Опублікувати скрізь" поле `brand` не передавалось — зберігалось як `NULL`, бот відображав такі товари в розділі "Інші рідини".  
Виправлення: `brand` додано до форми і до запиту INSERT.

**Товари додавались зі статусом "Немає в наявності"**  
Причина: `stock=0` був захардкоджений в endpoint.  
Виправлення: додано поле "Кількість" в форму контент-менеджера з дефолтним значенням `1`.

### 🟢 Мінорні

- `UnboundLocalError` в `restock_product` при помилці БД — змінні `waitlist` і `product` тепер ініціалізуються перед `try` блоком
- Зайвий `import json` прибрано
- `ADMIN_IDS` env var тепер використовується замість `ADMIN_TG_ID` (узгоджено між усіма роутами)

## Структура змін

```
vape_shop/
├── web/
│   ├── routes/
│   │   ├── content_manager.py   ← новий файл (ІІ контент, розсилка, додавання товару)
│   │   ├── products.py          ← фото upload, brand, waitlist notifications
│   │   ├── broadcasts.py        ← нова сторінка розсилок
│   │   └── auth.py              ← виправлено логін
│   └── templates/
│       ├── content_manager.html ← новий шаблон
│       ├── products.html        ← фото upload, brand поля
│       └── broadcasts.html      ← новий шаблон
└── bot/
    └── scheduler.py             ← виправлено повторні нагадування
```
