# ІІ Контент-менеджер — Технічна документація

## Що це і навіщо

Контент-менеджер — інструмент для автоматичної генерації маркетингових матеріалів за допомогою штучного інтелекту. Адмін вводить технічні дані товару, а AI пише готовий рекламний текст.

**Проблема яку вирішує:** написання продаючих постів і SEO-описів вручну займає час і вимагає навичок копірайтингу. З цим інструментом достатньо знати характеристики товару.

---

## Де знаходиться

**URL:** `/content-manager`  
**Файл роуту:** `vape_shop/web/routes/content_manager.py`  
**Шаблон:** `vape_shop/web/templates/content_manager.html`

## Як працює технічно

### Архітектура запиту

```
Браузер → POST /content-manager/generate
    → build_product_description()    # формує текстовий опис з полів форми
    → generate_text(PROMPT_TELEGRAM) # запит до Groq API
    → generate_text(PROMPT_SITE)     # запит до Groq API
    ← JSON { telegram: "...", site: "..." }
```

### AI модель

**Провайдер:** Groq  
**Модель:** `llama-3.1-8b-instant`  
**Чому Groq:** безкоштовний tier, дуже швидка генерація (менше 1 секунди)

### Промпти

Для кожного типу контенту — окремий system prompt:

**Telegram-пост:**
```
Ти — контент-менеджер вейп-шопу. Напиши продаючий пост для Telegram-каналу.
Стиль: живий і дружній, без агресивного продажу.
Виділи ключові характеристики товару і смакові ноти.
Додай заклик написати в бот для замовлення.
Використай емодзі помірно (3–5 штук).
Довжина: 150–220 символів.
Не вигадуй характеристик яких немає у вхідних даних.
```

**SEO-опис для сайту:**
```
Ти — SEO-спеціаліст інтернет-магазину. Напиши опис картки товару.
Структура:
  1. Перше речення — головна перевага (містить назву і бренд).
  2. Технічні характеристики — об'єм, склад, міцність якщо є.
  3. Смакова палітра — конкретні ноти (2–3 речення).
Вкажи ключові слова природно (назва товару, бренд).
Обсяг: 80–120 слів. Без "води" і загальних фраз.
Не вигадуй характеристик яких немає у вхідних даних.
```

**Ключовий принцип:** обидва промпти явно забороняють AI вигадувати характеристики — тільки те що ввів адмін.

### Формування user-повідомлення

Дані форми перетворюються в текстовий список функцією `build_product_description()`. Порожні поля пропускаються:

```
Товар: Манго Маракуя

Тип смаку: фрукти
Об'єм: 30 мл

```

## Кнопки після генерації

### 🔄 Регенерувати

Повторний запит до Groq з тими самими даними. AI завжди генерує різні варіанти навіть з однаковими вхідними даними — можна натискати до отримання бажаного результату.

---

### 📤 Розіслати клієнтам

Надсилає Telegram-пост всім підписаним клієнтам з бази даних.

До тексту автоматично додається:
> 👉 Переходь в каталог бота та обирай!

**З фото:** `sendPhoto` з текстом як підписом (`caption`).  
**Без фото:** `sendMessage`.

Результат зберігається в таблицю `broadcasts` (кількість доставлених і помилок). Якщо клієнт заблокував бота — помилка ігнорується, розсилка продовжується.

---

### 🌐 Додати на сайт

Зберігає товар в таблицю `products`. Після цього товар одразу з'являється на сайті і в боті в розділі відповідного бренду.

**Що зберігається в БД:**

| Поле | Значення |
|------|----------|
| `name` | назва з форми |
| `brand` | бренд з форми → визначає розділ в боті |
| `category` | категорія з форми |
| `description` | **AI-згенерований SEO-опис** |
| `price` | ціна з форми |
| `stock` | кількість з форми (дефолт: 1, одразу "в наявності") |
| `photo_id` | Telegram file_id якщо є фото |
| `is_active` | TRUE |

**Фото:** надсилається в адмін-чат Telegram → отримуємо `file_id` → зберігаємо в БД. На сайті відображається через проксі `/api/photo/{file_id}`.

---

### 🚀 Опублікувати скрізь

Виконує **обидві** попередні дії одночасно (`Promise.all` на фронтенді):
1. Telegram-розсилка всім підписникам
2. Збереження товару в БД

Один клік — товар опублікований скрізь.

## Можливі помилки

| Ситуація | Що побачить адмін |
|----------|-------------------|
| `GROQ_API_KEY` не налаштований | `⚠️ GROQ_API_KEY не налаштований` в полі тексту |
| Groq API недоступний або помилка | `⚠️ Помилка генерації: ...` з деталями |
| Немає підписаних клієнтів | Помилка: "Немає підписаних клієнтів" |
| Фото не завантажилось | Товар додається без фото |

## Ключові рішення при розробці

**Чому окремі промпти для TG і сайту?**  
Telegram і сайт мають різні вимоги: пост — короткий, емоційний, з емодзі. Опис для сайту — структурований, з ключовими словами, без емодзі. Один промпт не може добре закрити обидва формати.

**Чому Groq, а не OpenAI?**  
Groq має безкоштовний tier з достатніми лімітами для малого бізнесу і генерує відповіді значно швидше завдяки спеціалізованому обладнанню (LPU).

**Чому file_id, а не зберігати фото на сервері?**  
Railway не має persistent storage — файли зникають при редеплої. Telegram зберігає файли безкоштовно і назавжди. `file_id` залишається валідним, а існуючий проксі `/api/photo/{file_id}` вже підтримував цю архітектуру в інших частинах проекту.

**Чому stock=1 за замовчуванням?**  
При stock=0 товар одразу показується як "Немає в наявності" в боті і на сайті. Адмін може змінити кількість вручну, але за замовчуванням логічно що новий товар є в наявності.
